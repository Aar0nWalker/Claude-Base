# автопилот — self-driving mode

Run when the user types `/автопилот` (or says "autopilot", "develop yourself").
Goal: while there are no clear tasks, find improvements to {{PROJECT_NAME}} yourself, make
small verified slices, ship green changes to production, and report back — the user can step
away from the computer.

**Full procedure and guardrails are in `.claude/skills/base/autopilot/SKILL.md`. Read it before the first cycle.**

Deploy policy: ship to production every cycle, **only if everything is green and the tree is
clean of foreign work-in-progress**.

## Short version, per invocation

1. `./modules/bot/scripts/worker-bot.sh queue` (if wired up) — explicit tasks exist, do them first (autopilot yields).
2. Empty — top unclaimed item in `.agents/autopilot/backlog.md` (or `bash .claude/skills/base/autopilot/tools/gather-signals.sh`).
3. Claim in `.agents/wip.md`, one small slice, narrow check (`bash scripts/ci/check.sh <zone>`).
4. Green AND no foreign uncommitted changes → release per `docs/deploy-contract.md` → commit own paths + push → check health from outside + logs. Foreign WIP → commit the slice, defer the release. Red gate → revert the slice.
5. Sensitive zones (auth/admin/DB schema) — do not self-deploy; file under "Needs review" in the backlog.
6. `./modules/bot/scripts/worker-bot.sh status <agent> "cycle: …"` if wired up, mark the item in the backlog, remove your row from wip.
7. Not stopped → make sure a recurring schedule exists for the next cycle (~25-30 min) if not already set, then end the turn.

**Stop:** user says "stop autopilot" → cancel the recurring schedule + confirm. Stop yourself after 3 empty cycles or 3 red cycles in a row.
