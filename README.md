# Oridium Code Base

**Правила и пайплайн разработки для агента — под любой проект.** Клонируешь, говоришь Клоду
«сделай мне X», и разработка с первой минуты идёт так, как она идёт в боевом проекте: с планом
перед многофайловой правкой, тестом в том же изменении, проверкой перед каждым «готово» и гейтом,
который блокирует выкатку.

Здесь **нет кода приложения и нет стека**. Питон, раст, тайпскрипт, бот, игра, CLI — заготовка
одинаково применима, потому что переносит не решения, а дисциплину.

## Три шага

```bash
# 1. Клонируешь в папку нового проекта
git clone https://github.com/Aar0nWalker/Oridium-Code-Base .

# 2. Открываешь Claude Code и говоришь:
follow init.md
#    → короткое интервью (что делаем, чем, где живёт), заполнит PROJECT/STACK/ARCH,
#      поднимет скелет, СОБЕРЁТ ГЕЙТ под твой стек и покажет его зелёным и красным

# 3. Дальше просто работаешь
«добавь оплату», «почини вот это», «выкати»
```

Порядок в шаге 2 не случайный: гейт создаётся **до** первой фичи. Правило «проверь перед
выкаткой» — украшение, пока проверять нечем.

## Что внутри

| Область | Что даёт |
|---|---|
| **Правила** | `AGENTS.md`: оркестрация (кто планирует, кто исполняет, сколько сабагентов), обязательный минимум проверок, параллельная работа, обратная совместимость, безопасность, «готово когда» |
| **Гейт** | Универсальный раннер: убивает зависший прогон, сохраняет полные логи, отдаёт вердикт отдельной строкой. Что именно гонять — пишет агент под твой стек |
| **Сторожа** | «Тест — часть изменения» (поведение поменялось, а тесты нет → красный), запрет молча отключённых тестов, проверка переводов строк |
| **Скилы** | Планирование, реализация, дебаг с реестром багов, безопасность, ревью, UI, e2e, накопленные правила проекта, автопилот |
| **Реестр багов** | Показывает из истории, чинили ли уже эту зону: три фикса в одном месте — значит чинят симптом |
| **Память проекта** | `SESSION_HANDOFF.md`, архив чатов, зеркало сессий — новый чат входит в контекст за одну команду |
| **Параллельная работа** | Реестр занятых зон, дерево на агента, Telegram-бот с очередью задач |
| **Команды** | `выкати` · `контекст` · `запакуй` · `автопилот` |
| **Опционально** | Прокси-килсвитч — уровня машины, от стека не зависит |

## Чего здесь нет

Ни бэкенда, ни фронтенда, ни докера, ни деплой-скрипта — всё это свойства конкретного проекта.
Заготовка вместо готовых файлов даёт **контракты**: каким должен быть гейт
([docs/test-gate.md](docs/test-gate.md)) и каким должна быть выкатка
([docs/deploy-contract.md](docs/deploy-contract.md)). Агент создаёт их под проект на бутстрапе.

Раньше в этой ветке лежала SaaS-заготовка (FastAPI + Next.js + auth + админка). Она никуда не
делась — ветка `saas-starter-archive`.

## Что стоит знать

- **Гейт — единственный вердикт.** Внешнего CI нет. `bash scripts/ci/test-gate.sh` должен
  закончиться строкой `gate green`; красный гейт останавливает выкатку, а пропуск требует явной
  причины от владельца. Пока зоны не описаны, гейт **отказывается** работать — это специально:
  зелёный из-за того, что ничего не запустилось, хуже, чем никакого гейта.
- **Правила писались по шрамам.** Каждая строка в `AGENTS.md` появилась после того, как что-то
  сломалось. Поэтому заготовку и надо пополнять — как именно, описано в
  [docs/keeping-this-template-current.md](docs/keeping-this-template-current.md).
- **Параллельные агенты** делят одно дерево: перед правкой застолби зону в `.agents/wip.md`,
  коммить только свои файлы. Тесно — `scripts/agents/worktree.sh new <имя>` даёт своё дерево.
- **Свои скилы** пишутся по [.claude/skills/AUTHORING.md](.claude/skills/AUTHORING.md): описание,
  инструкция и `tools/` со скриптом. Скил без инструментов — недоделанный скил.

## Структура: база + два опциональных модуля

Репозиторий поделён на три независимые части. Нужна только первая — модули удаляются целиком,
и ничто в базе от них не зависит.

```
БАЗА — правила и пайплайн, ради этого всё и нужно
├── AGENTS.md                    # правила — грузятся каждую сессию
├── PROJECT.md STACK.md ARCH.md  # контекст проекта (заполняет бутстрап)
├── SESSION_HANDOFF.md           # снимок состояния для следующей сессии
├── init.md                      # бутстрап: интервью → контекст → скелет → ГЕЙТ → первый срез
├── scripts/ci/                  # раннер гейта + сторожа; zones/ пишет проект
├── scripts/agents/              # codemap · worktree · ротация сессий
├── docs/                        # контракты гейта и выкатки, поддержание заготовки
├── .claude/                     # CLAUDE.md · settings.json · commands/ · skills/base/
└── .agents/                     # реестр занятых зон · сессии

МОДУЛИ — по желанию
├── modules/bot/                 # Telegram-бот: ставить задачи агенту с телефона
└── modules/killswitch/          # весь трафик через прокси или сети нет
```

**[modules/bot](modules/bot/README.md)** — очередь задач через Telegram: ставишь задачу с
телефона, агент забирает, отвечает статусами и вопросами, понимает голосовые. Зависимостей нет,
запускается одним скриптом.

**[modules/killswitch](modules/killswitch/README.md)** — Clash: dev-трафик
идёт только через твой прокси, прямой выход отрезан фаерволом. Инструкция параметризованная —
попроси Клода настроить по ней, он подставит адреса твоей машины.

Удалить ненужный модуль — просто снести папку. Хук бота в `.claude/settings.json` при этом тихо
становится пустышкой и сессию не ломает.

## Плагины

Ставятся глобально в `~/.claude/`, в репозиторий не коммитятся, без них всё работает. Подробнее
в [PLUGINS.md](PLUGINS.md).

| Плагин | Зачем |
|---|---|
| **ponytail** | Режим «ленивого сеньора»: форсит простейшее рабочее решение, борется с оверинжинирингом |
| **Clash Verge Rev** | Прокси-клиент для килсвитча |
