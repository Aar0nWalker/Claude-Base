# Как устроена агентская база

## Что читает каждый агент

`AGENTS.md` — общий источник правил проекта. Codex подхватывает его напрямую; Claude импортирует
его из `.claude/CLAUDE.md`. Архитектура, стек и текущий handoff остаются общими файлами в корне —
вторую копию контекста для конкретного агента заводить не нужно.

## Скилы

| Агент | Каталог |
|---|---|
| Claude Code | `.claude/skills/base/<name>/SKILL.md` |
| Codex | `.agents/skills/base/<name>/SKILL.md` |

Содержимое базовых каталогов зеркальное. Каноническая авторская версия живёт в `.claude`; после
правки копируется весь каталог скилла в `.agents`, включая `tools/` и примеры. `SKILL.md` всегда
содержит frontmatter `name` и точный `description`: по описанию агент решает, когда его загрузить.
Скил читается полностью только по подходящей задаче — грузить весь каталог заранее не нужно.

## Команды

Claude-команды лежат в `.claude/commands/*.md`. Codex-команды оформлены как маленькие trigger-скилы
в `.agents/skills/commands/<command>/SKILL.md`. Пользователь может написать команду со слешем или
обычным текстом: `контекст`, `выкати`, `запакуй`, `автопилот`.

Назначение команды общее, технические детали могут различаться. Например, Claude архивирует свой
transcript, а Codex — свой rollout. Поэтому command-файлы не обязаны совпадать побайтно, но должны
вести к одному результату и соблюдать общий `AGENTS.md`.

## Как добавить или изменить

1. Общую политику менять в `AGENTS.md`, не дублировать её в двух agent-файлах.
2. Скил изменить в `.claude/skills/base/<name>/`, затем полностью обновить одноимённое зеркало в
   `.agents/skills/base/<name>/`.
3. Новую команду добавить отдельно в `.claude/commands/` и `.agents/skills/commands/`.
4. Проверить ссылки, frontmatter, исполняемые tools и отсутствие секретов.
5. Обновить таблицу README, если появился новый пользовательский shortcut.

Прикладные правила конкретного продукта сюда не переносятся: они живут в его `ARCH.md`, `STACK.md`,
learned-rules или собственных проектных скилах.
