# Прокси-килсвитч (опциональный модуль)

Весь трафик инструментов разработки и AI-агентов идёт **только** через ваш прокси. Прямой выход
физически заблокирован: упал прокси — инструменты теряют сеть целиком и **не** уходят в обход.

Зачем: без килсвитча «настроенный прокси» — это вежливая просьба. Любой инструмент, который
не прочитал переменную окружения (расширение редактора, обновлялка, дочерний процесс), пойдёт
напрямую, и вы об этом не узнаете. Килсвитч превращает утечку в честную ошибку сети.

Не нужен — удалите папку `modules/killswitch/` целиком. Ничего в заготовке от неё не зависит.

---

## Как это устроено

Два слоя, и это главное решение всей схемы:

```
  агенты (Claude, Codex — к API модели напрямую) ──┐
                                                   ├─→ Clash → ваш прокси → интернет
  всё остальное (git, пакетные менеджеры, curl) ───┘

  firewall / iptables: прямой выход, минуя Clash, — REJECT
```

**Ключевой принцип: адрес вашего прокси знает только Clash.** Все инструменты указывают на
локальный порт Clash. Сменить провайдера прокси = поменять сервер в Clash;
ни один конфиг инструмента не трогается. Без этого правила смена прокси превращается в обход
десятка мест, и один из них обязательно забудут.

| Компонент | Роль | Обязателен |
|---|---|---|
| **Clash Verge Rev** | единственный, кто знает адрес купленного прокси; локальный порт для всех | да |
| **Firewall-правила** | режут прямой выход в обход Clash — это и есть килсвитч | да |

## Настройка с Codex или Claude

Попросите: **«настрой килсвитч по modules/killswitch/README.md»** — и дайте ответы на вопросы
ниже. Схема зависит от вашей машины, поэтому конкретные адреса и пути агент подставит сам.

Что нужно решить заранее:

1. **Прокси.** Адрес, порт, логин/пароль вашего провайдера. Это единственный секрет во всей
   схеме, и он живёт только в конфиге Clash.
2. **Локальный порт Clash.** Любой свободный (у Clash Verge по умолчанию — свой, посмотрите в
   настройках). Дальше все конфиги ссылаются на него.
3. **Где вы работаете** — Windows, Linux, macOS, или Windows + WSL. От этого зависит, чем режется
   прямой выход и как процессы внутри WSL достают до Clash на хосте.

### Шаги

1. **Clash.** Поставьте [Clash Verge Rev](https://github.com/clash-verge-rev/clash-verge-rev),
   добавьте свой прокси, включите системный прокси. Проверьте, что через него ходит браузер.
2. **Переменные окружения инструментов.** `HTTP_PROXY` / `HTTPS_PROXY` на локальный порт Clash,
   `NO_PROXY=127.0.0.1,localhost,::1`. Задать нужно в трёх местах, и третье забывают чаще всего:
   - системные переменные пользователя,
   - конфиг редактора (терминалы и расширения наследуют не всегда),
   - профиль shell (`~/.profile`, `~/.zshrc`) — иначе процессы, запущенные не из редактора,
     пойдут мимо.
3. **git.** У него своя настройка, переменные окружения он читает не везде:
   `git config --global http.proxy http://127.0.0.1:<порт>`.
   Осторожно: мёртвая запись здесь ломает `push` с невнятной ошибкой TLS — если прокси сменился,
   правьте и её.
4. **Килсвитч.** Правила фаервола, режущие исходящие в обход Clash:
   - Windows: `scripts/killswitch-on.ps1` / `killswitch-off.ps1` (из PowerShell от админа);
   - WSL/Linux: `scripts/wsl-killswitch.sh` — iptables default-deny с разрешением на адрес Clash.
   Внутри WSL хост виден по адресу из `/etc/resolv.conf`, **не** по `127.0.0.1`: это первая
   причина, по которой «всё настроил, а не работает».
5. **Агенты.** Claude Code и Codex ходят к своим API напрямую, через те же `HTTP(S)_PROXY` →
   Clash. Прослойки-сжимателя (`ANTHROPIC_BASE_URL` на локальный прокси) не ставим: она ничего
   не экономит на подписке и режет слова из правил и результатов инструментов.

### Проверка — обязательная

Настройка без проверки ничего не значит: килсвитч, который не проверяли, обычно не работает.

```bash
# 1. через прокси ходит и видно ваш внешний адрес
curl -sS https://api.ipify.org ; echo

# 2. ГЛАВНОЕ: выключите Clash — сеть у инструментов должна ПРОПАСТЬ, а не пойти напрямую
#    (если ответ пришёл, килсвитч дырявый: ищите инструмент, который не читает переменные)
curl -sS --max-time 10 https://api.ipify.org ; echo "exit=$?"
```

Второй тест и есть смысл всей затеи. Прогоняйте его после каждой правки схемы.

## Диагностика

| Симптом | Обычная причина |
|---|---|
| Работает в редакторе, не работает в терминале | переменные заданы не в профиле shell |
| `git push` падает по TLS, остальное живо | у git своя настройка прокси, и она протухла |
| Из WSL прокси не виден | указан `127.0.0.1` вместо адреса хоста из `/etc/resolv.conf` |
| Всё «настроено», но выключение Clash не роняет сеть | правила фаервола не применились — килсвитча нет |
| Агент молчит, сеть вроде есть | `ANTHROPIC_BASE_URL` смотрит на мёртвую прослойку — уберите его |
| Инструмент в контейнере не видит прокси | внутри контейнера `127.0.0.1` — это сам контейнер |

Раньше здесь лежал разбор конкретной машины автора — с адресом купленного прокси, личными
путями и внутренними IP. Он убран намеренно: чужие адреса в инструкции сбивают с толку, а
секретам в репозитории не место. Схема выше описывает ровно ту же конструкцию, но параметрами,
которые вы подставляете свои.

Свою настройку держите вне репозитория: пароли — в Clash, локальные адреса — в переменных
окружения, ничего из этого не коммитьте.
